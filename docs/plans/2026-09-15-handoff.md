## 1. O que é o gasclaw, em uma frase

Um framework agêntico completo rodando **100% dentro do Google Apps Script** (sem servidor externo), onde cada
agente é uma **pasta do Google Drive** com markdown (`AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`,
`BOOTSTRAP.md`, `MEMORY.md`, `skills/<nome>/SKILL.md`), inspirado no OpenClaw/Eve mas adaptado às limitações do GAS
(6 min por execução, 30 s no Chat, escopos OAuth granulares, Properties de 9 KB/500 KB, Cache de 100 KB/6 h).

Regras não-negociáveis (`CLAUDE.md` do projeto): zero servidor externo, agente = pasta sem executar código vindo
dela, `minimal-code` sempre ativo, **toda melhoria sobre limite do GAS precisa de POC medida em `poc/` + ADR em
`docs/adr/`**, zero operação manual pós-setup (`./gasclaw <comando>`).

### 🟠 P1 — Loop durável (F2): construído e ligado, falta medir

Este foi o foco desta sessão inteira. **Problema resolvido:** o Apps Script mata execuções em 6 min e o Chat espera
resposta em 30 s; antes, uma tarefa longa terminava em "Parei por tempo" e **o trabalho já feito era jogado fora**.

**O que está pronto, testado e publicado (dev v44):**
- `src/run.ts` — núcleo puro: `DurableRun`, lease de 6 min, teto de 4 tentativas (contam **falhas**, não passos),
  teto de custo de **US$ 0,10/tarefa** com pausa+continuar, e a regra de nunca repetir uma ação com efeito
  interrompida (`inflight`).
- `src/runStore.ts` — estado em `.gasclaw/runs/<runId>.json` na pasta do agente (fonte da verdade); fila de
  ponteiros `R:` nas Script Properties (separada da `Q:` do trace).
- `src/runner.ts` — o pump: `pumpOnce` dá um passo, `pump` dá vários enquanto houver tempo/orçamento.
- `src/main.ts` — ação `step` (POST + segredo CLI, em `MUTATING`), `stepDeps()` que monta o turno via `chatTurn`

  `runAsk` (cria run, tenta responder em 20 s), `runState` (polling), `runDecide` (aprovar/negar/responder/continuar).
- `src/chat.html` — reescrita para usar `runAsk`/`runState`/`runDecide` em vez do `chatSend`/`chatClick` síncrono;
  mostra "trabalhando…", o custo acumulado e sobrevive a fechar a aba.
- **ADR-026** (`docs/adr/026-run-duravel.md`) registra tudo, com a tabela de POCs pendentes.
- 662 testes verdes, `tsc` limpo, tudo commitado até `5c0ab72`.

1. **Fechar a POC P3** (o pump não come cota de gatilho de 90 min/dia): registrar `p3: (step) => pocP3(step)` no
   mapa `POCS` do `main.ts` + criar o modo `synthetic=1` na ação `step` (só no build de dev, roda tool falsa sem

## 4. Achados de medição que já mudaram o desenho (não repetir os mesmos erros)

- **Tentativas do run contam falhas, não passos.** Erro do desenho original: um run de 20 passos bons morreria na
  4ª volta do pump. Corrigido antes de publicar.
- **Desistir precisa ser um desfecho explícito**, não um sumiço: ponteiro esgotado ficava para sempre na fila e a
  tela diria "Trabalhando…" eternamente. `claimNext` devolve `exhausted: true` para o pump gravar a falha honesta.
- **Retomar sem decisão não pode inventar uma decisão** (`{approved: true}` de fachada faria a próxima tool pular o
  card de aprovação = auto-aprovação silenciosa). `resume?: Snapshot & { decision?: Decision }` — decisão opcional,
  com teste provando que retomar sem decisão volta a pedir aprovação.
- **P95 com nearest-rank, não `⌊0.95·n⌋`** — a fórmula antiga caía no último elemento com n=20, ou seja, "p95" era
  na verdade o máximo. Lição: um teste escrito pela mesma cabeça que escreveu a fórmula confirma a intenção, não a
  verdade — use vetor pequeno calculado à mão para testar régua estatística.
- **P18 (custo da sessão no Drive): confirmado em 2 medições (10 e 20 amostras) — mediana ~700-800ms, acima da meta
  de 300ms.** A leitura inicial de "é ruído da base" estava errada; o Drive é estável, quem oscilava era o cache.
  Resolvido pela decisão #4 acima (lote).
- **C7 da P16 (rodízio de modelos gratuitos):** o turno chamava `/key` do OpenRouter a cada turno para saber
  `is_free_tier`, estourando o teto de 3 chamadas/30min. Corrigido: **o turno nunca consulta `/key`**; usa contador
  local + cache de horas; só o painel (sob pedido do usuário) lê fresco.

## 5. Como operar tudo (guia de referência)

### Comandos do dia a dia (`./gasclaw <comando>`, sempre a partir de `~/Projects/gasclaw`)

```bash
./gasclaw up            # publica no dev (build + testes + push + verificação de HEAD/versão)
./gasclaw up --prod      # publica em prod (mesma URL)
./gasclaw down/restart   # pausa / down+up
./gasclaw status [--prod]  # IDs, URLs, implantações, health
./gasclaw doctor [--prod]  # diagnostica e diz como corrigir
./gasclaw open [--prod]    # abre a tela gasclaw no navegador
./gasclaw poc <id> [etapa] # roda uma POC no dev (ex.: poc p18, poc p3 zero)
./gasclaw eval <cenário|--all> [--model id]  # roda evals/*.md
./gasclaw trace [id]     # árvore de passos de um run (sem id: o mais recente)
./gasclaw usage [AAAA-MM-DD]  # custo por modelo
./gasclaw limits [--fresh]    # painel de limites (Google + OpenRouter)
./gasclaw runs           # abre a planilha "gasclaw — execuções"
```

**Lock automático:** todo comando que publica ou mede usa `lock_dev` (`${XDG_CACHE_HOME:-$HOME/.cache}/gasclaw/dev.lock`)
para impedir duas publicações/medições simultâneas — não rode dois `./gasclaw` em paralelo manualmente.

### Testes e build local (sem publicar)

```bash
npx tsc --noEmit          # typecheck — deve dar "No errors found"
npx vitest run             # 73 arquivos, 662 testes — se o `tail`/pipe cortar a saída, rode sem grep primeiro
```

> Nota de ambiente: este projeto tem um hook `rtk` (Rust Token Killer) que reescreve comandos automaticamente
> (`git status` → `rtk git status`). Se `npx vitest run` parecer travar ou dar erro de parser estranho, prefixe com
> `rtk proxy` (ex.: `rtk proxy npx vitest run`) para pular o filtro.

### Como checar que algo está de verdade funcionando (não confiar em "parece que sim")

1. **Sempre** rodar `npx tsc --noEmit` + `npx vitest run` antes de publicar — nunca publicar árvore vermelha.
2. Depois de `./gasclaw up`, conferir a saída: precisa dizer "bundle conferido", "HEAD remoto conferido", "versão N
   conferida: idêntica ao build", e `health: {"ok":true,...}`. Se qualquer um faltar, **não está publicado direito**.
3. Para testar o pump/run durável manualmente por fora, sem esperar o gatilho de 1 min:
   ```bash
   URL="<web app dev>"; SECRET=$(grep CLI_SECRET .env.local | cut -d= -f2)
   T=$(gcloud auth print-access-token); JOB=$(openssl rand -hex 8)
   curl -sL -o /dev/null -X POST -H "Authorization: Bearer $T" \
     --data-urlencode "action=step" --data-urlencode "secret=$SECRET" --data-urlencode "job=$JOB" "$URL"
   sleep 4
   curl -sL -H "Authorization: Bearer $T" "$URL?action=job&id=$JOB"   # deve devolver {"ok":true,"status":"done",...}
   ```
4. Para conferir a tela: `curl "$URL?page=chat"` deve conter `runAsk`, `runState`, `runDecide` (é o que o teste
   `test/p17.test.ts` também garante, junto com "nunca innerHTML/eval/chave/microfone").
5. **Nunca** declarar algo medido/resolvido sem rodar a POC de verdade no dev — é regra do `CLAUDE.md` do projeto.

## 6. Como as duas "pistas" (Motor / Observabilidade) foram usadas nesta sessão

Esta sessão coordenou dois subagentes de longa duração em worktrees separados, trocando mensagens via `SendMessage`:
- **Pista Motor** (worktree `~/Projects/gasclaw-motor`): dona de `agent.ts`, `chat.ts`, `tools/`, `evals/`, POCs de
  medição (P3, P11, P16, P18).
- **Pista Observabilidade** (implícita, trabalhava em `main` também via subagente): dona de `main.ts`, `gasclaw`
  CLI, painel, docs (PROGRESS/CHANGELOG/ADRs).

**Ambos os subagentes desapareceram** quando esta conversa foi retomada (troca de modelo/sessão) — `ListAgents`
mostra "No reachable agents". **Se quiser retomar esse padrão**, é preciso relançar via `Agent` tool com
`isolation: "worktree"` apontando para os mesmos diretórios, e reler o estado deles (`git log` em cada worktree,
como fiz no início deste handoff) antes de dar instruções novas — não assuma que eles lembram de nada.

Regra que funcionou bem e vale manter: **cada mudança de contrato entre pistas (tipos em `agent.ts`: `Snapshot`,
`Pending`, `Decision`, `TurnResult`) precisa ser avisada antes de ser feita**, porque as duas pistas dependem dela.
Isso evitou pelo menos uma auto-aprovação silenciosa (ver §4).
